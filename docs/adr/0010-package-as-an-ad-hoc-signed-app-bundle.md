# 0010. Package as an ad-hoc signed app bundle

- Status: accepted
- Date: 2026-10-26

## Context

Running a binary from a terminal is fine for development, but people expect to double-click an app.
A Finder-launched app also has a smaller environment than a shell (no Homebrew on PATH, nowhere to
print errors).

## Decision

`scripts/package-macos.sh` assembles `dist/Handset.app` from the release binary, an `Info.plist` and an
icon generated by `frames/make_icon.py`, then signs it **ad hoc** (`codesign --sign -`). Inside the
bundle the app defaults to `--audio` (see ADR 0007), and it locates `adb` and `ffmpeg` itself and reports
fatal errors in a dialog.

The bundle is not notarised and has no Developer ID signature.

## Alternatives considered

- **cargo-bundle or cargo-packager:** more features, but one more tool for a short script.
- **A Developer ID signature plus notarisation:** the right answer for distribution, needs a paid
  Apple developer account, and is left for when there is something to distribute.
- **Only ship the command-line binary:** simpler, but not what most people want.

## Consequences

- It runs on the machine that built it. On other Macs Gatekeeper will warn about an unidentified
  developer until the app is signed and notarised.
- The first save may trigger macOS's prompt to let Handset write to Pictures and Movies.
- Follow-up: Developer ID signing, notarisation and a universal (arm64 + x86_64) build.
